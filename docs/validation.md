# Проверки версии 0.1.0

Дата: 2026-09-05. Хост: macOS arm64, JDK 21.0.12.1. Android Emulator 37.1.11,
образ `system-images;android-34;android-tv;arm64-v8a`, экран 1920×1080,
программный renderer SwiftShader. Это не телевизор Philips.

## Сборка и статические проверки

- `./gradlew --no-daemon :particle-dream:assembleDebug :particle-dream:lintDebug`
  — **BUILD SUCCESSFUL**, Lint: **0 ошибок, 1 предупреждение**. Предупреждение
  сообщает о более новом Gradle; в проекте намеренно закреплена совместимая
  с AGP 8.13.2 версия Gradle 8.13. Ошибки Lint не подавлены.
- `bash tools/test-engine.sh` — **PASS**: детерминированное движение,
  сходимость к цели, смена сцен, 10 минут моделирования без нечисловых значений
  и выхода за границы, возврат после паузы, отклонение недопустимых целей.
  Это моделируемое время, не 10 минут измерения GPU.
- `apksigner verify --verbose .../particle-dream-debug.apk` — **Verifies**,
  подпись APK Signature Scheme v2, один signer.
- SHA256 Gradle Wrapper JAR совпал с опубликованным Gradle значением:
  `81a82aaea5abcc8ff68b3dfcb58b3c3c429378efd98e7433460610fecd7ae45f`.
- Сборка также предупреждает о разных версиях XML схемы SDK и устаревших
  возможностях Gradle. Это предупреждения инструментов; сборка завершается успешно.

## Проверки Android-приложения

`bash tools/test-android.sh emulator-5580` — **PASS**:

- По умолчанию включены три различные непустые сцены животных, фразы выключены.
- Экран настроек запускается, редактор фраз присутствует.
- При импорте JPEG с EXIF orientation=6 изображение 80×40 становится 40×80.
- Оригинал не изменяется, своя картинка заменяет стандартные сцены.
- Ошибка декодирования новой картинки сохраняет предыдущую.
- Удаление своей картинки восстанавливает три стандартные сцены.

Скрипт использует собственный framework Instrumentation runner без JUnit/AndroidX.
Он рассчитан только на отдельный эмулятор и очищает настройки приложения в нём.

## Наблюдение в эмуляторе

- Запуск предпросмотра кнопкой D-pad Center и возврат кнопкой Back работают.
- Просмотрены реальные скриншоты настроек и анимации с формированием ретривера,
  бобтейла и рэгдолла. После осмотра граничные отражения заменены переносом
  частиц на противоположную сторону, чтобы поток не накапливался у краёв.
- Автоматический запуск проверен при `screen_off_timeout=15000`,
  `screensaver_activate_on_sleep=1`, выбранном компоненте нашего dream и отключённом
  `stay_on_while_plugged_in` **только внутри одноразового эмулятора**.
  `dumpsys dreams` показал `ParticleDreamService`, `isPreview=false`,
  `mBound=true`; `dumpsys power` — `mWakefulness=Dreaming`.
- Нажатие D-pad Center завершило dream: после перехода `mCurrentDream=null`.
- `logcat -d -s AndroidRuntime:E` после работы предпросмотра не содержал ошибок.
- Стандартный intent `android.settings.DREAM_SETTINGS` в этом образе не разрешается
  ни в одну Activity. Приложение обрабатывает этот случай сообщением; выбор
  компонента для проверки был задан через ADB внутри эмулятора.
  Прямая команда `cmd dreams start-dreaming` оказалась недоступна без root,
  поэтому фактически проверялся запуск по таймеру бездействия.

## Что не проверено

Установка и выбор заставки в меню Philips 65PUS8729/60, его конкретная прошивка,
плавность/нагрев на реальном GPU, длительная работа на ТВ и все варианты
системных файловых picker. Целевой лимит около 30 кадров/с не является
измеренным показателем на Philips. Windows-сборка не запускалась.

Выпуск содержит debug APK, а не приложение с постоянным release-ключом.
